# RSUの権利確定と記帳済み給与の集計

[English](vesting.md) | **日本語**

権利確定した株式（整数株）の円換算額を、パッケージ内の関数で端数まで正確に計算します。仕訳で未入力になっている株式側の借方金額と給与側の貸方金額は、同時に補完します。両方の明細に記録した権利確定の根拠が一致することを検証し、ローカルの帳簿にある全仕訳から、暦年の給与収入を集計します。

給与の記録だけなら、有価証券・外貨のパッケージは不要です。権利確定より後の投資取引を扱う場合に、その二つを別途選択します。このパッケージにはバインディング6に対応するエンジンが必要です。

## 対象となる状況を確認する

利用者の実際の状況が、次のすべてに当てはまることを確認してください。

- 通常の従業員向けRSUで、株式で交付される（株式決済）
- 対象期間を通じて日本に居住し、日本で勤務している
- 国内の源泉徴収票に含まれていない
- 日本で源泉徴収されていない
- 税は確定申告で自分で納める

これらは利用者ごとに確認する事実で、勤務先の会社名から一律に決まるものではありません。純額決済（net settlement）、国内給与への算入、海外勤務、外国税額控除には対応していません。別に対応した処理が必要です。納税資金を作るための株式売却（sell-to-cover）を前提にはしません。

## 帳簿を設定する

帳簿は暦年・円建て・scale 0（小数桁なし）にします。設定に書く勘定科目は、省略せずにフルパスで指定します。

```yaml
units: [{symbol: AMZN, scale: 0}]
jp_rsu:
  scope_confirmed: true
  included_in_salary_statement: false
  japan_withholding: false
  tax_funding: self-assessment
  income_account: Income:RSU
  share_account: Assets:AMZN
  share_unit: AMZN
```

株式の単位は、数量のscaleを0にしてください。円換算のレシピが扱うのは整数株だけです。パッケージは、帳簿に宣言した単位のscaleを検査します。取得費はこのパッケージでは計算せず、別途選択するパッケージが扱います。給与科目は、上で確認した条件のRSU専用にしてください。通常の給与やその他の収入は、別の科目に記録します。

## 円建ての権利確定額を計算する

原資料で、認識日、ドル建ての株価、円／ドルの為替レートを確認します。小数は浮動小数点で渡さず、整数の係数と小数桁数（scale）で指定してください。例えば100.25ドルは係数`10025`・scale `2`、1ドル150.1250円は係数`1501250`・scale `4`です。

```sh
iris overlay recipe jp-rsu.vesting-value --set scope_confirmed=true \
  --set quantity=100 --set price_coefficient=10025 --set price_scale=2 \
  --set fx_coefficient=1501250 --set fx_scale=4 --set rounding=truncate
```

正確な計算結果は1,505,003.125円で、明示した切り捨てにより`gross_jpy: 1505003`となります。`half-up`は0.5以上の端数を切り上げます。丸め方の既定値はありません。適用する扱いを確認して選択してください。このパッケージは、指定された計算を行うだけです。入力した株価や為替レートが正しいことは保証せず、法令上どの評価方法・端数処理を使うべきかも判断しません。

対応範囲は、株数が1～1,000,000株、株価と円／ドルの為替レートがそれぞれ正の値で1,000,000以下、小数桁数がそれぞれ0～8です。ゼロ・負の値・範囲外の入力、未対応の丸め方、丸めるとゼロになる評価額は拒否します。

関数は整数だけで計算します。商と余りに分けてドル段階の端数を為替換算まで保持し、最後の円換算額だけを丸めます。単純に掛け合わせるとint64を超える場合でも、その積を作らずに計算するので、対応範囲内なら計算途中の値も結果も桁あふれしません。

出力の`gross_jpy`と`valuation`を確認してください。必要なら、`--apply --out filings/rsu-valuation-vest-1.md`を付けて、確認した結果を保存します。保存したファイルには計算に使ったパラメータがすべて残るので、あとで同じ計算を再実行できます。レシピは計算結果を返すだけで、仕訳の金額は書き換えません。

明細書、株価と為替レートを確認した日付、計算の根拠は`raw/`に保存し、仕訳からは通常の添付として参照してください。`valuation_source`は、根拠資料の場所を示すだけです。このパッケージは、添付ファイルの内容をハッシュで照合せず、本物かどうかも確認しません。

## 権利確定を仕訳に記録し、金額を補完する

株式側の借方明細と給与側の貸方明細に、同じ権利確定の情報を記録します。金額の根拠として、計算に使った`valuation`の入力値をそのまま記録するか、確認済みの正の`gross_jpy`を記録してください。確認済みの円換算額だけを記録する従来の書き方も使えます。その場合は`valuation`を省略します。

```yaml
lines:
  - account: Assets:AMZN
    debit: null
    quantity: 100
    unit: AMZN
    jp_rsu: &vesting
      event_id: amazon-2026-05
      grant_id: grant-1
      payer: Amazon.com Inc.
      recognition_date: '2026-05-01'
      valuation_source: raw/vesting-2026-05.pdf
      valuation:
        quantity: 100
        quantity_scale: 0
        price_coefficient: 10025
        price_scale: 2
        fx_coefficient: 1501250
        fx_scale: 4
        rounding: truncate
  - account: Income:RSU
    credit: null
    jp_rsu: *vesting
```

仕訳日は`recognition_date`と一致させます。`iris journal complete`を実行すると、両方の明細の金額をプレビューできます。内容を確認し、ほかの仕訳補完と同じように、返されたリビジョン（`revision`）を指定して適用してください。

補完と検証は次のように動作します。

- 両方の金額が未入力でも補完できます。補完にはIrisの汎用機能（検証付きの仕訳変更案）を使い、計算式そのものはパッケージ内にあります。
- Irisは2明細の変更案をひと組として検証し、記録済みの金額は変更しません。記録済みの金額が計算結果と矛盾する場合は、補完を拒否します。
- `valuation`を記録した場合は、検証のたびに同じ関数で再計算し、数量、両明細の金額、別に記録した`gross_jpy`を検査します。計算入力の欠落や範囲外の値は、検証エラーになります。
- 現金・源泉徴収・売却の明細は作りません。

記帳と集計の前に、`iris validate`で帳簿全体を検証し、問題をすべて解消してください。記帳するかどうかは、帳簿の持ち主が別に判断します。

## 暦年の追加給与収入を集計する

`jp-rsu.salary`には、`scope_confirmed=true`、設定済みの`income_account`、同じ暦年の年初と年末を指定します。

```sh
iris overlay recipe jp-rsu.salary --set scope_confirmed=true \
  --set income_account=Income:RSU --set from=2026-01-01 --set to=2026-12-31
```

確認した結果は、`--apply --out filings/rsu-salary-2026.md`を付けると保存できます。ほかのレシピと同じく、計算条件も一緒に記録されます。ローカルMCPでは、仕訳補完に`complete_journal`を使います。集計には`run_recipe`を使い、`recipe: jp-rsu.salary`と同じパラメータを渡します。CLIもMCPも、既定では結果を表示するだけです。リモートMCPでは、これらの操作を実行できません。

集計の対象は、記帳済みの給与だけです。集計には次がそろっている必要があります。

- 株式側と給与側の明細に、互いに一致する権利確定の根拠が記録されている
- `event_id`が重複していない
- 根拠のある正の給与総額が記録されている
- 専用科目の明細に、必要な項目がすべて記録されている

次の場合は集計を拒否します。イベントの重複、根拠の欠落、株式側・給与側の片方にしかない根拠、金額の不一致、科目の誤り、取消仕訳、1年に満たない期間や年をまたぐ期間の指定です。

レシピはローカルの帳簿の全仕訳を読み、記帳済みの各仕訳の構造・実際の日付・数量を検査してから、根拠を集計します。これとは別に、通常の帳簿検証（`iris validate`）も必要です。この検査も資料のパスも、添付ファイルが本物であることまでは確認しません。権利確定イベントに漏れがないかは、証券会社や勤務先の記録と照合して確認してください。帳簿にまったく記録されていない権利確定は、レシピには推定できません。

出力は、上で確認した条件のRSUによる、追加の給与の**収入金額**です。RSUだけで別に計算した給与所得の金額でも、納める税額でもありません。ほかの給与の収入金額と合算してから、給与所得控除を適用してください。

保存した結果には、`inputs_sha256`と、集計元の仕様のバージョンが記録されます。帳簿に保持されているパッケージと、変更されていない元の記録があれば、同じ結果を再計算できます。元の記録が変わると、保存した結果とは一致しなくなります。有価証券・外貨の方針の保持と、取得費の翌年度への引き継ぎは、別途選択するそれぞれのパッケージが受け持ちます。

## 株式の売却、為替差損益の実現、年度繰越へ進む

株式を売却したときの申告用の数値を準備するには、`jp-securities-basis`を別途選択します。このパッケージは、通常の購入で取得した株式と、RSUの権利確定で取得した株式を、同じプール（取得費を通算する範囲）に入れて計算します。

売却で受け取ったドルを通常の現預金として持つ場合は、`jp-foreign-currency`を選択します。このパッケージは、出金側と入金側を対にして記録した本人名義口座間の移動では、取得費をそのまま引き継ぎます。その後に実現した為替差損益は、給与や株式の譲渡損益とは分けて計算します。

どちらのパッケージでも、対応範囲を確認し、対象の科目をもれなく設定してください。`jp-rsu`を選択しただけで、これらが自動的に有効になることはありません。

年度の繰越には、既存の`iris yearend`を使います。先に、検証済みのパッケージをインストールして選択しておいてください。繰越では、数量、帳簿価額、端数処理後の配分取得費（帳簿価額とは別に保持する税務上の取得費）を、それぞれ別の値として引き継ぎます。翌年度の帳簿をローカルに作るには、`iris yearend --local --to ../book-2027 ./book-2026`を実行します。繰越時に保持される定義と出所情報により、翌年度の帳簿は単独で動作します。繰越によって、給与が翌年度にもう一度計上されることはありません。繰越の前に、元の記録に漏れがないことと、同じ日の取引の順序が仕訳ファイルのパス順で正しく表されていることを確認してください。

帳簿の全仕訳を読む処理が扱えるのは、帳簿の1年度につき仕訳4096件までです。エンジンのデータ量・実行量の上限も適用されます。対応していない記録や不完全な記録がある場合と、上限を超えた場合は、エラーで止まります。名前付きビューでの申告資料の作成・年度繰越と、承認済みの会計世代への対応は、Iris本体でまだ完成していない別の開発項目です。これらのパッケージが出力するのは申告準備資料であり、提出済みの申告書ではありません。

### 数値例を一連の取引として確認する

100株を1株100米ドル、1米ドル150円で権利確定した場合、株式の取得額と追加の給与収入はそれぞれ1,500,000円です。そのうち40株を4,800米ドル、円換算696,000円で売却すると、取得費は600,000円、株式の譲渡益は96,000円となり、60株・取得費900,000円が残ります。受け取った4,800米ドルを、設定に指定した本人名義の口座の間で移しても、円建ての取得費696,000円はそのまま引き継がれます。その後744,000円に円転した場合の為替差益48,000円は、給与や株式の譲渡益とは別に計算します。

[株式のガイド](../../jp-securities-basis/guides/shares.ja.md)と[外貨のガイド](../../jp-foreign-currency/guides/cash.ja.md)で、それぞれの設定を確認してください。各タスクのテスト例には、売却、口座移動、円転と、翌年度の状態を用意しています。取引ごとに原資料と照合してください。この数値例には手数料を含みません。別に記録した対象の手数料がある場合の計算は、各ガイドで説明しています。

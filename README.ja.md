# IrisBooks 地域オーバーレイ

[English](README.md) | **日本語**

[IrisBooks](https://irisbooks.jp) の地域ごとの記帳・税務ルールを、YAML と
[CEL](https://cel.dev) で書いたものです。`iris` エンジンは特定の国について何も
知りません。国によって異なる部分は、地域ごとに 1 つのディレクトリとしてここに
置いています。どの資産がどの償却の特例を使えるか、消費税の明細行にどの税区分を
付けるか、申告の集計値を帳簿からどう組み立てるか、といった部分です。これらは
エンジンの上に重ねて使うため、「オーバーレイ」と呼んでいます。

| パス | 内容 |
|---|---|
| `<id>/overlay.yaml` | id、バージョン、必要なバインディングのバージョン |
| `<id>/functions.yaml` | 以下のすべてで共有する名前付きの CEL 関数 |
| `<id>/rules/` | チェック。`iris validate` が実行し、クラウドも書き込みのたびに実行します |
| `<id>/recipes/` | 計算。出力は根拠付きで記録され、再計算で照合されます |
| `<id>/derive/` | 未入力のフィールドに `iris validate --fix` が提案する値 |
| `<id>/tests/` | 上記すべてのテストケース（入力と、期待する結果の組） |

## 帳簿がオーバーレイを使うしくみ

`iris` の各リリースには、ビルドした時点までに公開されたすべてのバージョンの
オーバーレイが組み込まれています。帳簿は検証に使うバージョンを `config/book.yaml` で固定します。この
リポジトリのタグ名が、そのまま固定に書く値になります。

```yaml
region: JP
overlay: jp@2026.09.1   # = このリポジトリのタグ jp@2026.09.1
```

固定が勝手に動くことはなく、手で書き換えることもしません。動かすのは
`iris overlay upgrade` です（最新のバージョンへ。`--to <id>@<version>` で指定も
できます）。新しいバージョンを検証し、そのテストを実行してから固定を書き換えます。
お使いの `iris` のビルドより後に公開されたバージョンは、このリポジトリの署名付き
リリースとして届きます。`iris overlay fetch` は帳簿が固定しているバージョンを
ダウンロードして検証し、IrisBooks のクラウドも同じバージョンで評価します。
どちらのコマンドも `iris` v0.2.0 以降が必要です。

公開済みのバージョンの中身も変わりません。レシピが計算した償却表や申告の集計値は、出どころ
として `overlay: jp@<version>` を記録します。`iris validate` はそのバージョンで
レシピを再計算し、記録された値が入力から正しく計算されたかを確かめます。

オーバーレイが持つのは**計算方法**であり、**率**ではありません。償却率、
みなし仕入率、経過措置の控除割合のように、税制改正で計算方法は変わらずに値だけが
変わるものは、レシピのパラメータにしています。その期間の値はユーザーの AI が
調べて帳簿に記録します。ここに表として置くことはしません。

帳簿は `config/overlays/` に独自のルールやレシピを重ねられます。詳しくは
[帳簿ファイル形式リファレンス](https://irisbooks.jp/manual/ja/book-format-reference/)
にあります。ひとつの帳簿を超えて役立つ層があれば、このリポジトリへの
プルリクエストをお待ちしています。手順は [CONTRIBUTING.ja.md](CONTRIBUTING.ja.md)
にまとめています。

## テストを実行する

```sh
iris overlay test --dir jp
```

`--dir` には `iris` v0.2.0 以降が必要です（[インストール](https://irisbooks.jp/start)）。
CI でも、プルリクエストのたびに最新の署名付きリリースを使って同じテストを
実行します。

## 免責事項

オーバーレイは、帳簿に記録された内容をチェックし、計算します。税務上の助言では
なく、税理士の代わりにもなりません。
